# Glossary

> Domain-specific terms used throughout the AI Entity Index plugin.

---

## Core Terms

### Entity

A named real-world thing — person, organization, location, product, event, etc. — extracted from your WordPress content by the AI pipeline. Each entity is stored as a single record in the `wp_ai_entities` table with a canonical name, type, status, and optional semantic links (Wikipedia, Wikidata).

### Mention

An edge connecting an entity to a specific post where it appears. Each mention has a confidence score and a context snippet showing the surrounding text. Mentions are stored in `wp_ai_mentions`.

### Alias

An alternative surface form for an entity. For example, "Apple Inc." and "AAPL" are both aliases that resolve to the canonical entity "Apple". Aliases are created during deduplication and can be manually managed in the Entity Drawer.

### Canonical Entity

The authoritative record for a real-world thing. When duplicate extractions are found, they are merged into a single canonical entity. All aliases point back to this one record.

### Confidence Score

A float between 0.0 and 1.0 indicating how certain the AI model is that an extraction is correct. Scores are mapped to tiers:

| Tier   | Range        | Behavior                       |
|--------|--------------|--------------------------------|
| High   | 0.85 – 1.0   | Automatically accepted.        |
| Medium | 0.60 – 0.84  | Accepted (adjustable).         |
| Low    | 0.40 – 0.59  | Accepted but may need review.  |
| Reject | < 0.40       | Discarded by default.          |

### Schema.org JSON-LD

A structured data format injected into the `<head>` of your WordPress pages for SEO and AI discoverability. The plugin uses an `@graph` pattern containing an `Article` node linked to entity-specific nodes (Person, Organization, etc.).

### Propagation

The process where changes to an entity (name, type, semantic links) trigger regeneration of Schema.org JSON-LD for every post linked to that entity. Propagation uses recursive self-scheduling via Action Scheduler to handle large numbers of posts without timing out.

## Pipeline Terms

### Extraction Pipeline

The six-phase background process that reads your WordPress content, extracts named entities, resolves duplicates, creates links, updates indexes, and generates structured data. Runs entirely through Action Scheduler jobs.

### Preparation (Phase 1)

Collects post IDs matching the selected post types and strips HTML to produce clean plain text for AI processing.

### Extraction (Phase 2)

Sends prepared text to the AI model for named entity recognition. The model returns identified entities with types, confidence scores, and context snippets.

### Deduplication (Phase 3)

Compares newly extracted entities against existing records. Resolves aliases and merges duplicates so each real-world thing has exactly one canonical entity.

### Linking (Phase 4)

Creates mention records connecting entities to the posts where they appear. Each mention stores the confidence score and context snippet from extraction.

### Indexing (Phase 5)

Updates aggregate mention counts on each entity and verifies that database indexes are consistent with the current data.

### Schema Build (Phase 6)

Generates Schema.org JSON-LD for each processed post and caches it in `post_meta`. This is the structured data that search engines and AI crawlers read.

## Knowledge Base Terms

### Knowledge Base (KB)

A RAG-ready content index built from your WordPress content. The KB chunks posts into segments, generates vector embeddings, and exposes semantic search endpoints for AI applications to query your content by meaning rather than keywords.

### Document

A KB representation of a WordPress post. Each document tracks the source post, indexing status, chunk count, and metadata. Stored in `wp_ai_kb_docs`.

### Chunk

A semantically-bounded content segment split by heading boundaries, typically around 450 tokens. Chunks are the fundamental unit of the KB — each one is embedded and searchable independently. Stored in `wp_ai_kb_chunks`.

### Embedding

A vector representation of a chunk's semantic meaning, generated by an AI embedding model. Embeddings enable similarity-based search by comparing the mathematical distance between vectors. Stored as packed floats in `wp_ai_kb_vectors`.

### Vector

A mathematical representation of text as an array of floating-point numbers (e.g., 1536 dimensions). Vectors capture semantic meaning so that text with similar meaning produces vectors that are close together in vector space.

### Anchor

A stable, deterministic identifier for a chunk. Format: `kb-{12-char-hash}`. The same content always produces the same anchor, making it reliable for linking and deduplication even across reindexes.

### Semantic Search

Finding relevant content by comparing vector similarity rather than exact keyword matching. A query is converted to a vector, then compared against all chunk vectors to find the closest matches.

### Cosine Similarity

The distance metric used to compare vectors. Returns a score from 0.0 to 1.0 where 1.0 means identical meaning and 0.0 means completely unrelated.

### Top-K

The number of search results to return from a semantic search query. Default is 8. Adjustable in the KB Test Search page from 1 to 20.

### RAG (Retrieval-Augmented Generation)

A pattern where relevant content is first retrieved from a knowledge base using semantic search, then provided as context to an AI model for generation. The KB pipeline makes your WordPress content RAG-ready.

## AI Publishing Terms

### llms.txt

A standard text file for AI crawlers that describes your site's content in a machine-readable format. Available at `/llms.txt`, with a REST mirror at `/wp-json/vibe-ai/v1/kb/llms-txt`. AI assistants and crawlers fetch this file to understand what your site covers.

### AI Sitemap

A machine-readable sitemap listing KB documents with chunk counts and content hashes. Available at `/ai-sitemap` or `/ai-sitemap.json` for JSON, `/ai-sitemap.xml` for XML, with a REST mirror at `/wp-json/vibe-ai/v1/kb/sitemap`. Helps AI crawlers discover and track changes to your indexed content.

### Change Feed

A JSON feed of recently modified KB documents, designed for incremental syncing. Available at `/changes`, with a REST mirror at `/wp-json/vibe-ai/v1/kb/feed`. AI crawlers can poll this endpoint to get only what changed since their last visit, rather than re-crawling the entire site.

## Technical Terms

### Action Scheduler

A WordPress background job processing library (originally built by WooCommerce). The plugin uses it to run all pipeline jobs — extraction, indexing, propagation — without blocking the admin interface or timing out PHP.

### Circuit Breaker

A reliability pattern that stops API calls to the AI service after repeated failures. After 5 consecutive failures, the circuit breaker activates and enforces a 5-minute cooldown before retrying. This prevents burning through API quota when the upstream service is down.

### Batch Size

The number of posts processed in a single pipeline job. Dynamically adjustable between 5 and 50. Larger batches process content faster but consume more memory and API quota per job.

### OpenRouter

A model-agnostic AI API gateway that the plugin uses for both entity extraction and embedding generation. OpenRouter provides access to multiple AI models through a single API, letting you switch models without changing code.
